# INVARIANTS — постоянные правила «не трогать»

> **Читать ПЕРЕД любой доработкой.** Это правила, которые действуют ВСЕГДА, независимо от задачи. Каждое из них уже один раз стоило поломки или было явно установлено владельцем. Нарушение = регрессия.
>
> Копия этого файла лежит и во фронте (`finance-dashboard/INVARIANTS.md`) — держать синхронно.

---

## 🔴 РМК / касса

1. **ПК-версия РМК — БЕЗ изменений UI.** Любые доработки интерфейса — ТОЛЬКО в мобильной версии. ПК-верстку не трогать.
2. **Кассир НЕ генерирует штрихкоды.** Только скан и печать существующих. Генерация — вне кассы.
3. **`qty` = число сканов, поле readonly.** Кассир не редактирует количество вручную.
4. **Единица измерения всегда «шт».** Не вводить другие единицы.
5. **Финмодуль не реализуем.** Не добавлять финансовый модуль в РМК.

## 🔴 Данные и точки

6. **Тест-точку «Интернет магазин» (`b2f8ef62-368f-11ed-8788-40a3ccea3566`) НЕ удалять.**
7. **Классификатор безопасности: запись в прод-1С — только с явного согласия владельца.** Чтение/диагностика — свободно. WRITE-action-ы (`sell`, `open-shift`, `close-shift`, `return-item`, `return-receipt`, `build-orp`, `variant-sync`, `anomalous-resolve`) не дёргать автоматически.
8. **Прямой доступ к 1С OData даёт 401** — работать ТОЛЬКО через backend-прокси.

## 🔴 Учёт (бизнес-логика)

9. **Возвраты учитываются ВЕЗДЕ и ВСЕГДА.** Чистая выручка = продажи − возвраты. Действует в: Обзор, Статистика, Кассовый отчёт. Формула системная — применяется к любому периоду. (smoke.sh проверяет этот инвариант автоматически.)
10. **`history` = только продажи** (возвраты отфильтрованы). **`returns` = только возвраты.** Не смешивать.

## 🔴 Технические лимиты 1С OData (эмпирические, НЕ превышать)

11. **`fetchPaymentsByRefs`: CHUNK=15, CONC=16.** При CHUNK>15 → URL слишком длинный (404/414). При CONC>16 → 1С отклоняет соединения (HTTP 500 «operation aborted»).
12. **`vercel.json`: `maxDuration=300`.** Не опускать — иначе 504 на sales-report за месяц (нужно ≈93с).
13. **Нельзя:** `$expand=Оплата` (→501), фильтр `Ref/Date` на строках оплат (→400). Способы обхода уже перепробованы — не повторять.

## 🔴 Валюта / локаль

14. **Валюта — сомони, обозначение «с.».**
15. **Время данных РМК/1С — по Душанбе (+05).**
16. **Язык интерфейса и общения — русский.**

## Процесс изменений (чтобы не ломать)

- **Перед деплоем backend:** `node -c api/pos.js` → `./smoke.sh` (baseline) → деплой → `sleep 45` → `./smoke.sh` (после). Есть `[FAIL]` — откат (ROLLBACK.md).
- **Перед деплоем фронта:** проверка синтаксиса → `./deploy.sh` → Ctrl+F5 → визуальная проверка.
- **Меняешь формат ответа action-а:** сначала обнови `API-CONTRACT.md` И фронт, только потом деплой. Иначе фронт сломается молча.
- **Новый action:** добавь его в `API-CONTRACT.md` и, если это READ, в `smoke.sh`.

## История поломок (чтобы не повторять)
- Фикс `position:fixed` на ценнике сломал печать → всегда проверять печать после верстки ценников.
- KPI «Возвраты» был захардкожен в 0 → возвраты теперь считаются реально, не хардкодить.
- CONC=32 положил 1С → предел 16.
